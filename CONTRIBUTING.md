# Contributing to spack-agent

Thank you for your willingness to contribute to spack-agent. We welcome all types of contributions, irrespective of size and complexity.

### Types of contributions
- [Issues](#issues)
- [Pull requests](#pull-requests)

**All contributions to spack-agent must adhere to our [Code of Conduct](CODE_OF_CONDUCT.md), which is based on [The European Code of Conduct for Research Integrity - Revised Edition 2023](http://www.doi.org/10.26356/ECOC).**


## Issues
Issues are generally used to remind or inform yourself or others about certain things in the
software. We use them to report bugs, start a feature request, or plan tasks.

To create an issue, select one of our templates and provide a detailed description.

Before opening a new issue, please check whether your bug has
already been reported within the existing issues. Opening an issue is a valid contribution on its own and does not mean you
have to solve it yourself.


## Pull requests

### 1. Setup of spack-agent
Set up spack-agent as described in the [README.md](README.md)

### 2. Code development

Add your changes to the codebase. Please add (unit) tests that capture your changes.

#### Commit messages
Please provide meaningful commit messages.

### 3. Submit a pull request
Once you submitted your pull request, checks will run automatically to verify that your changes do not break existing functionality. We will review your changes before it can be merged into the `main` branch.
We desire a clean commit history. This may require rebasing the commits before merging.

## Documentation
As this project is still rather small, code is documented directly in the code. Furthermore, the [README.md](README.md) should be kept up to date to help users get spack-agent running. We welcome any improvements to our documentation.

## AI-assisted contributions
Any AI-assisted code must be reviewed, understood, and validated by the contributing author, who takes full responsibility for the contribution. Specifically, contributors must ensure that AI-assisted code:
* does not introduce third-party code incompatible with the project's [MIT license](LICENSE)
* adheres to our [code of conduct](CODE_OF_CONDUCT.md) and this contributing guide.
